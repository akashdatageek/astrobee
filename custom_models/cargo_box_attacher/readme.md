\page cargoboxattacher Cargo Box Attacher

This package provides a Gazebo world plugin that welds two models together
with a fixed joint on request, so that Astrobee can pick and place the cargo
boxes provided by the \ref cargobox package.

## Why a weld instead of a physical grasp

Astrobee's arm is a perching arm, not a manipulator: it is designed to clamp
known-geometry ISS handrails so the robot can park. In simulation
(`simulation/src/gazebo_model_plugin_perching_arm/`) the gripper joints are
driven by PID position controllers only — there is no grasp detection, no
contact constraint and no attach logic, so closing the gripper on a free box
penetrates or ejects it. This plugin takes the `gazebo_ros_link_attacher`
approach instead: the caller decides when a pick succeeds and requests a weld
between a gripper link and a box link. This is deterministic and scriptable,
which is what a pick-and-place *behaviour* demo needs. A contact-based
alternative (`gazebo_grasp_fix` from `gazebo-pkgs`) exists but requires
tuning and is sensitive to the friction values of the box model.

## Services

The plugin is loaded by `simulation/worlds/iss.world` and advertises:

- `/sim/cargo/attach` (`cargo_box_attacher/Attach`) — weld `model_1/link_1`
  to `model_2/link_2` with a fixed joint
- `/sim/cargo/detach` (`cargo_box_attacher/Attach`) — release a weld
  previously created by attach

If this package is not built, Gazebo logs an error for the missing library
at world load and the simulation continues without grasp support.

## Example

Deploy the arm and close the gripper on a box (visually), then weld:

    rosservice call /sim/cargo/attach "model_1: 'bsharp'
    link_1: 'top_aft_gripper_left_distal_link'
    model_2: 'cargo_box_1'
    link_2: 'body'"

Move the robot; the box follows. Release it at the destination:

    rosservice call /sim/cargo/detach "model_1: 'bsharp'
    link_1: 'top_aft_gripper_left_distal_link'
    model_2: 'cargo_box_1'
    link_2: 'body'"

The gripper link names are generated by
`description/description/urdf/macro_perching_arm.urdf.xacro` and are prefixed
by namespace and bay (`${prefix}${bay}_gripper_left_distal_link`). Do not
guess them from the xacro — verify the runtime names with
`rostopic echo /joint_states -n 1` and use the model name reported by
`rostopic echo /gazebo/model_states -n 1` for `model_1`.
